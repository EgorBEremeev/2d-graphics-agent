# 2D Graphics Agent

Расширяемая конфигурация Codex для работы с двухмерной графикой с помощью готовых графических программ, их нативных команд и API. Агент анализирует графическую задачу, выбирает подходящие средства, управляет ими и проверяет результат. Конфигурация охватывает растровые и векторные изображения, форму, цвет, композицию и подготовку выпуска.

Основа работы — возможности существующих графических средств: например, нативные операции Inkscape, трассировка Potrace и операции библиотек Pillow и Shapely. Состав не ограничен этими примерами: агент может подобрать и освоить другие подходящие средства. Карта операций и матрица помогают выбрать совместимый интерфейс; предметные навыки и проектные утилиты описывают и связывают отдельные маршруты.

**Среда:** подготовка и использование конфигурации рассчитаны на Windows с установленным `uv`. Необходимые графические приложения и зависимости подготавливаются для выбранной задачи; они не входят в репозиторий.

## Возможности

Конфигурация направляет агента при анализе, создании и преобразовании изображений, выборе и сочетании графических операций, обработке растровых и векторных данных, геометрических преобразованиях, компоновке и подготовке выпуска. Средства выбираются с учётом задачи и подтверждённых возможностей. В существующую библиотеку входят следующие маршруты:

- **Векторизация контрастного эскиза:** получение замкнутых редактируемых SVG-областей с сохранением значимых отверстий и связей.
- **Нумерация цветных областей:** создание контурной схемы и карты цветов из подготовленного SVG.
- **Компоновка документа:** размещение готовой схемы, образцов и легенды на редактируемых страницах.
- **Геометрия и печать:** изгиб по эллиптической дуге, распределение по кривой, выпуск PDF с заданным масштабом и разбиение на листы.

Доступность конкретной операции зависит от входных данных, выбранного интерфейса и подготовленной среды. Полный перечень маршрутов и условия выбора — в [карте операций](docs/agent/operations.md); фактические границы исполнителей и исторические свидетельства — в [матрице возможностей](docs/agent/capability-matrix.md).

## Начало работы

1. Откройте корень репозитория в Codex как доверенный проект. Проектные [инструкции агента](AGENTS.md) и конфигурация задают порядок работы с графическими задачами.
2. Передайте агенту исходный файл и опишите, что требуется получить: например, редактируемые контуры, нумерованную схему или печатный файл. Укажите важные ограничения: размеры, масштаб, формат, сохранение объектов и другие условия задачи.
3. При необходимости агент подготовит компоненты по [регламенту среды](docs/environment/setup.md). Состав подготовки определяется выбранной операцией. Фактические компоненты и их расположение фиксируются в [карте среды](docs/environment/2d-environment.md).
4. Проверьте полученные файлы и отчёт агента. В отчёте должны быть указаны результат, использованные средства, параметры и существенные ограничения.

Например, задание может звучать так: «По этому контрастному эскизу подготовь редактируемый SVG с отдельными замкнутыми областями; сохрани отверстия и покажи наложение на исходник». Для печати укажите требуемые физические размеры, формат листа и масштаб.

## Как расширять возможности

Если задача выходит за рамки подтверждённых маршрутов, агент ищет подходящее готовое средство в официальных источниках, проверяет совместимость с Windows, лицензию и контракт операции, затем выполняет минимальную проверку нового интерфейса. Подходящая существующая возможность используется повторно; при отсутствующем стыке её можно адаптировать, сохранив рабочий процесс. Новая узкая утилита создаётся для подтверждённого пробела и получает явный вход, выход, параметры и обработку ошибок.

Подтверждённые сведения об интерфейсе, его ограничениях и результате вносятся в [матрицу возможностей](docs/agent/capability-matrix.md); при появлении нового класса задач обновляется [карта операций](docs/agent/operations.md). Так конфигурация развивается вместе с набором применимых графических средств.

## Как устроен репозиторий

| Раздел | Назначение |
|---|---|
| [AGENTS.md](AGENTS.md) и `.codex/config.toml` | Операционные инструкции и подключение проектных принципов для Codex. |
| [docs/](docs/README.md) | Индекс документации, карта операций, матрица возможностей, контракты данных и инструкции по среде. |
| [.agents/skills/](.agents/skills/) | Предметные навыки векторизации, нумерации и компоновки. |
| [tools/](tools/README.md) | Вызываемые скрипты и требования к средствам для конкретных маршрутов. |
| `requirements-graphics.txt`, `requirements-plotter.txt` | Закреплённые зависимости для графического и отдельного факультативного plotter-окружения. |

Конфигурация различает художественную геометрию, физическое изделие и страницу документа. Между ними требуется явное соответствие координат и масштаба. Подробнее — в [текущих контрактах данных](docs/agent/graphics-data-contracts.md).

## Ограничения и проверка результата

- Командные средства и headless-рендер доступны для работы агента; управление интерактивным графическим интерфейсом выполняется по прямому разрешению пользователя.

## Файлы и окружение

Окружения, загруженные приложения, кэши, личные исходники и результаты исключены из Git. Для своих материалов можно использовать `inputs/`, для рабочей проверки — `artifacts/`, для готовой выдачи — `deliverables/`. Эти каталоги создаются по необходимости; их содержимое при переносе рабочего пространства нужно сохранять отдельно. Правила исключений и предусмотренные контрольные SVG приведены в [.gitignore](.gitignore).

Для использования уже подготовленных компонентов в новой сессии см. [runtime](docs/environment/runtime.md). Если нужно изменить подключённые инструкции, см. [устройство конфигурации и синхронизацию](docs/agent/configuration.md). Все документы доступны через [индекс документации](docs/README.md).

# Project Brief — `inkscape-cli-mosaic-labeler`

**Версия:** 4.2 · **Дата:** 11.11.2026  
**Тип:** самостоятельное задание на альтернативный SVG-labeling Domain Skill  
**Проект:** `C:\gitCreative\solo-learn-mosaic` · **Режим:** headless SVG/geometry runner, а не имитация GUI.

**Режим проверок:** штатный вызов уже подтверждённого маршрута не сопровождается повторным `--help`, discovery, хешированием промежуточных файлов, DOM-diff после каждой команды или независимым рендером каждой стадии. Тестовые fixtures ниже предназначены для **однократной приёмки нового/изменённого навыка** и адресной регрессии после изменения его контракта. В обычном задании выполняется минимальная проверка конечного результата; промежуточная диагностика — при неизвестном интерфейсе, наблюдаемом сбое или реальном риске потери геометрии/масштаба. Не создавать подробный QA-log при штатном успешном исполнении.

## 1. Назначение и альтернативность

Предоставить воспроизводимую компетенцию для обработки **существующих цветных художественных SVG**: извлечение видимых цветовых зон, назначение устойчивой палитры, формирование контурной схемы, автоматическое размещение номеров в областях и проверка редактируемого результата. Это **альтернатива** `vector-svg-to-numbered-contours` на базе адаптированного `paintbynumbersgenerator`, а не последовательная стадия после него.

Предпочтение готовым и проверенным инструментам/расширениям сохраняется, но при отсутствующем полноценном headless label placement допускается проектный узкий runner, использующий действительные библиотеки и CLI. Наличие слова `inkscape` в названии **не означает**, что всю геометрию создаёт нативный движок редактора: исполнитель обязан указать, какие функции реализованы `inkex`, какие Shapely/polylabel, какие `inkscape.com --query-all`/export, а какие добавлены им самим.

Skill не подготавливает фото/эскиз, не создаёт тайлы, не задаёт миллиметровые швы, не делает физическую раскладку и не компонует лист с легендой.

## 2. Вход, выход, неизменяемые свойства

**Вход:** `artwork_regions.svg`, `vtracer_output.svg` или другой SVG с замкнутыми видимыми цветными областями; optional `artwork_regions.manifest.json`, готовая/переданная `palette_map.json`; `preserve_geometry` default, пороги площади/узкости в SVG units, настройки шрифта/stroke относительно изображения, правила tiny zones `keep/merge/flag`, конфиг разрешённых SVG features.

**Домен A, без физических mm.** `viewBox` и набор исходных зон сохраняются при `preserve_geometry`. Для производственных PDF, если запрошены, создаётся отдельный A→P print profile с ясным page mapping; сам labeler не определяет размер изделия.

**Выход:**

- `structural_layout.svg` — редактируемые контуры, отдельный слой меток, `zone_id/color_id` и корректные callouts; заливка может быть снята только в выходной схеме, исходный SVG не изменять.
- `palette_map.json` — детерминированное отображение `color_id/palette_id → number/color`, одинаковый цвет имеет один номер без слияния раздельных зон.
- `qa_summary.json` — результаты топологии, labels visibility, text fit, warnings, точный CLI/runner provenance.
- `preview_overlay.png` — независимо отрендеренная схема и сравнение контуров с входом.

Дополнительный PDF не требуется без отдельного job. `zone_id` не подменяет `tile_id`, физические швы не формируются.

## 3. Техническая реализация и инструментальные границы

Перед проектным кодом:

1. Инвентаризировать реально установленные Inkscape extensions, `inkex`, `Shapely`/polylabel, нативный Inkscape CLI/actions, существующий `tools/extensions/mosaic_labeler.py`, проектные skills и capability matrix. Не полагаться на документированные где-то версии без локального вызова.
2. Проверить существующие headless extensions для label-placement и paint-by-numbers, лицензии, параметры, обработку `<path>`, transforms, holes, styles, high object count.
3. Провести независимые малые probes: `inkscape.com --query-all` для размеров и текста, SVG structure parsing, поиск label point, рендер и выходная геометрия. `--action-list` подтвердить по установленному бинарнику. `copy/paste-in-place` **не** считать выполненным по коду 0; для объединения документов использовать `document-assembly`, а не GUI clipboard.
4. Если готовая extension не имеет вызываемого headless интерфейса, использовать проектный runner с честным перечислением библиотек. Само наличие `.inx` не доказывает работоспособность без GUI.

**`cli-anything-inkscape`:** для локальной JSON-only обёртки входной формат — собственная JSON-модель, а не существующий SVG. Не направлять в неё `artwork_regions.svg`; не вызывать для произвольного SVG parse/edit и не выдавать её за real Inkscape CLI. Оригинальный сторонний `SKILL.md` сохранить, прочитать проектный `LOCAL_LIMITATIONS.md`, если он есть, и использовать native CLI/runner по подтверждённой capability matrix. В самом `.agents/skills/inkscape-cli-mosaic-labeler/SKILL.md` **не** должно быть обязательной зависимости от JSON-only harness.

Учитывая реальный код, выбирать наиболее узкий и поддерживаемый способ интеграции: `inkex` — SVG/model API; Shapely — геометрические операции над нормализованными видимыми контурами; `inkscape.com --query-all` — измерение bounding boxes/текстовых размеров; Inkscape CLI — renderer/export. `--query-all` сам не создаёт метки и не является гарантией точных bbox для всех экзотических SVG constructs. Не писать custom SVG path parser вместо проверенного существующего решения.

## 4. Алгоритм областей, палитры и номеров

**Нормализация:** распознавать все применимые shapes/path, inherited fill/style/opacity, `transform`, `viewBox`, visible clipping, fill-rule, holes, z-order; строить понятную модель **видимой зоны**, а не просто XML списка элементов. Неподдержанные `use/filters/masks` преобразовывать проверенным способом или выдавать reasoned diagnostic; не терять область тихо.

**Палитра:** агрегировать реальные цвета с явно установленной политикой близких оттенков (по умолчанию сохранять исходные идентификаторы и не квантовать автоматически). Порядок номера определяется переданной map либо устойчивой canonical сортировкой; независим от расположения `path` в DOM и генерации случайного UUID.

**Микрозоны:** threshold площади и min-width в A units (или долях области). `keep` оставляет зону, `flag` создает warning/callout, `merge` допускается лишь в явном режиме и с подтверждением изменения геометрии/площади/смежности; `delete` по умолчанию недопустим.

**Позиция номера:** внутри геометрической видимой области с отверстием; centroid допускается только после point-in-surface test. Проверить font bounding box, margin to boundary, ориентацию и пересечения меток. Для узких областей — callout anchored to `zone_id` либо `LABEL_UNFIT` diagnostic, не переносить номер в соседнюю область и не скрывать его.

**Выход:** сохранить исходные `zone_id`, раздельные paths/groups, palette IDs, редактируемые номера на отдельном layer и явные stroke units. После экспорта заново parse+rasterize SVG; проверить, что цветовые contours совпадают в `preserve_geometry` в пределах тестового tolerance.

## 5. CLI и конфигурация Skill

Путь `.agents/skills/inkscape-cli-mosaic-labeler/SKILL.md` с валидными `name`, `description`. Положительный trigger: *vector SVG labeling through Inkscape extension/inkex geometry runner, numbered colored facets*. Исключить photograph pre-vectorization, physical tile cutting, page assembly.

Точный CLI инструментов/runner определяется по их действительному интерфейсу. Для проектного `tools/extensions/mosaic_labeler.py` при его наличии обеспечить проверяемую CLI-справку `--input`, `--palette`, `--out-svg`, `--out-map`, `--out-preview`, `--mode`, `--config` (если такие флаги ещё не существуют, **реализовать** их как проектный контракт либо документированно выбрать несовпадающий интерфейс, не выдавая пример за реальную команду). Никакого хардкода номера палитры/путей/зон для конкретной картинки.

`SKILL.md` должен давать законченный алгоритм invocation+validation и fallback. Конкретные команды/versions/local limits хранятся в capability matrix и supporting references; AGENTS содержит только маршрут на класс задания и правило одного labeler.

## 6. Приёмочные тесты и существенные риски

| Fixture | Что обязано проверяться |
|---|---|
| L1 — простой SVG с 3–5 цветами | Все цветовые классы и зоны пронумерованы, карта палитры детерминирована |
| L2 — несколько зон одного цвета | Один номер, раздельные `zone_id`/контуры, нет merge |
| L3 — вогнутая область, отверстие, остров | Метки внутри **видимой** геометрии, не в hole или вне path |
| L4 — shared Bezier boundary, transforms, CSS styles | Сохранность топологии и border structure при preserve_geometry |
| L5 — очень узкие/малые зоны | Реальный text-fit / callout / warning, no silent missing labels |
| L6 — VTracer SVG, множество путей | Поддержка/явный отказ по ресурсоёмкости, точная attribution CLI |
| L7 — external SVG→JSON-only harness | Кандидат отвергается на Input Gate; нет `JSONDecodeError` в основном workflow |
| L8 — headless operation returns code 0 but no geometry effect | `NO_OP_UNEXPECTED`, смена маршрута без интерактивного GUI |

**Приёмка нового или изменённого labeler:** на итоговых fixtures убедиться, что метки присутствуют и находятся в видимых областях, соответствует палитра, сохраняются существенные контуры и читается preview. Для сложных зон использовать геометрический point-in-surface; замеры всех bbox, полные DOM-diff, повторные прогоны и профилирование времени требуются только при конкретной проблеме. При штатном использовании контролировать только конечную схему; правильная идемпотентность не считается отказом.

**Поведение при целевой приёмке маршрута:** в общей новой Codex-сессии при естественном запросе «сделать нумерованную контурную схему из цветного SVG» агент выбирает этот route только при его фактической пригодности, использует headless runner и фиксирует, какие части сделали `inkex`, geometry lib и нативный exporter. При наличии принятого адаптированного paintbynumbers route сравнивает по envelope; **не** исполняет оба последовательно.

**Итоговые статусы:** **PASS** — реальный headless runner создаёт корректную редактируемую нумерованную схему и есть evidence QA/вызова; **FAIL** — нарушена топология, потеряны номера, неправильно выбрана обёртка, либо запуск не меняет результат при ожидаемой операции; **UNPROVEN** — нужный исполнитель или проверка не запускались; **BLOCKED** — названа конкретная недостающая зависимость/разрешение. Не подменять эти статусы отметкой об обнаружении файла `SKILL.md`.

## 7. Этапы и поставка

**Stage 1:** inventory подтверждённых средств и минимальные probes только неизвестных интерфейсов → **Gate:** список подтверждённых средств и честные ограничения.  
**Stage 2:** выбор готовой реализации/узкого runner → **Gate:** решение с обоснованным функциональным пробелом.  
**Stage 3:** нормализация видимых зон, палитра и labels → **Gate:** L1–L5.  
**Stage 4:** CLI/Skill integration, true renderer, negative tests L6–L8 → **Gate:** real invocation+QA.  
**Stage 5:** new-session behavioral test и fallback на alternative labeler → **Gate:** воспроизводимый trace.  
**Stage 6:** scoped Git, verified capability matrix, code/fixture/report, сохранение исходников.

Если уже есть работоспособный `mosaic_labeler.py`, выполнять только необходимую доработку, не создавать параллельный labeler. Отсутствие права установки extension в пользовательский профиль не оправдывает его скрытую модификацию; проектная локальная реализация и headless runner предпочтительнее.

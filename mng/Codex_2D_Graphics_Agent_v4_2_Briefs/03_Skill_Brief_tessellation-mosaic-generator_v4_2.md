# Project Brief — `tessellation-mosaic-generator`

**Версия:** 4.2 · **Дата:** 11.11.2026  
**Тип:** самостоятельное задание на проектный Codex Agent Skill  
**Проект:** `C:\gitCreative\solo-learn-mosaic` · **Режим:** воспроизводимый геометрический CLI/API workflow.

**Режим проверок:** штатный вызов уже подтверждённого маршрута не сопровождается повторным `--help`, discovery, хешированием промежуточных файлов, DOM-diff после каждой команды или независимым рендером каждой стадии. Тестовые fixtures ниже предназначены для **однократной приёмки нового/изменённого навыка** и адресной регрессии после изменения его контракта. В обычном задании выполняется минимальная проверка конечного результата; промежуточная диагностика — при неизвестном интерфейсе, наблюдаемом сбое или реальном риске потери геометрии/масштаба. Не создавать подробный QA-log при штатном успешном исполнении.

## 1. Предмет и целевой результат

Создать, подключить либо довести до принятого состояния предметную компетенцию **физической раскладки отдельных элементов мозаики по художественным направляющим (andamento)**. Исходник — уже существующие замкнутые художественные области, полученные из эскиза, фото или готового SVG. Skill самостоятельно формирует переход от artwork-координат к геометрии изделия в миллиметрах, затем направления движения рядов, размещение, подрезку, швы, обработку микроэлементов и проверяемые физические выходы.

**Запрещено** подменять криволинейный орнамент глобальной прямоугольной сеткой, декорировать изображение нарисованными квадратами без индивидуальных границ деталей, переносить швы назад в исходный artwork или выдавать художественные цветовые зоны за физические плитки. Не выполнять без запроса первичную векторизацию, очистку фото и нумерацию *цветовых областей*: маркировка отдельных изготовляемых деталей — самостоятельная задача и не заменяет художественную палитру.

Skill должен быть применим к отдельному панно, полосовому/ленточному рисунку, эллиптической направляющей и криволинейным зонам. Конкретные размеры, шаг «1 блок», 4–5 волн, A4 и размеры полуосей относятся к **job parameters**, а не вшиваются в код или в универсальную skill policy.

## 2. Входные интерфейсы и координатные преобразования

**Обязательные источники:** `artwork_regions.svg` (при наличии — совместимый `C_lay_boundaries.svg`) и `artwork_regions.manifest.json` с зонами, стабильными `zone_id/color_id`, `viewBox`, fill-rule/holes/transforms и исходным происхождением. Исходные файлы не изменять.

**Параметры manufacturing:** форма изделия или точные физические опорные ограничения; способ отображения artwork→physical; допуск деформации (по умолчанию нет); базовые размеры/формы и вариация тайлов, minimum usable width/area, допуск реза, `tile_gap_mm`, тип/приоритет направляющих, количество цветов, handling cut tiles, острые углы, узкие полосы, стратегия отбраковки/ручной установки. Если физических данных для реального изготовления нет, процесс останавливается с `BLOCKED_MISSING_PHYSICAL_CONSTRAINTS`: недостаток касается именно производства, не валидности художественного SVG.

**Домен A→B:** хранить отдельное `scale_mapping.json`: исходный `viewBox`, единицы и габариты изделия, матрица/описание допустимой нелинейной деформации, mapping control points, error bounds. Для криволинейной поверхности/дуги определить, измеряется ли длина по дуге, по хорде или в плоскости развертки. Искажать мотив молча нельзя.

**Промежуточные файлы:** `scaled_artwork.svg` (A в B без тайлов), `flow_lines.svg` (линии/поля andamento с zone IDs), `raw_tiles.svg`, `clipped_tiles.svg`, отдельный report об исключённых/переупакованных микроэлементах.

**Выходы:**

- `final_layout.svg`: реальные отдельные редактируемые замкнутые геометрии с `tile_id`, `zone_id`, `color_id`, размерностью в мм, слоями материала/направляющих/маркировки, ясной картой к source.
- `tiles_manifest.json`: `schema_version`, mapping, площадь, размеры и минимальная ширина каждой детали, ID, материал/цвет, положение, ориентация, варианты подрезки, соседство, gap policy, statuses и provenance.
- `qa_summary.json` и `layout_preview.png`: measured scale/gaps/overlaps/voids, visual andamento и соответствие исходным зонам.
- `mosaic_assembly_scheme.pdf`: печатная технологическая схема при постановке print/assembly profile, где фактическая геометрия соответствует 1:1 и каждая PDF page box проверена. Многолистовая раскладка листов/легенда может передаваться `document-assembly` без изменения B-геометрии.

## 3. Поиск инструментов, адаптация, граница кода

На стадии разработки один раз сверить `AGENTS.md`, route map, capability matrix и пригодность реально доступных CAD/vector/geometry tools. Проверка `--help`/версии/одного fixture нужна только неизвестным или изменённым интерфейсам. Кандидаты: существующие Inkscape extensions, нативный Inkscape CLI/path actions (отдельно от `cli-anything-inkscape`), CAD constrained/sketch/array mechanisms, `vpype`, геометрические библиотеки для Boolean/offset/robust intersections, специализированные опубликованные tiling/andamento algorithms. `cli-anything-freecad` только если действительно подтверждает нужную метрическую CAD-операцию; установка ради наличия skill не оправдана.

Обёртка `cli-anything-inkscape`, если принимает собственный JSON и не открывает произвольные SVG, **не должна** получать `artwork_regions.svg` как вход. Не предполагать, что действия native Inkscape имеют ту же семантику, что методы стороннего harness. Для ранее не проверенной критической Boolean операции провести одну безопасную пробу на overlapping shapes с ожидаемыми IDs; принятый и неизменный интерфейс повторно не тестировать.

При отсутствии рабочего узкого готового алгоритма разрешена **проектная параметризованная реализация только размещения/перепланировки/расчёта поля**, используя библиотечную геометрию; не писать полный собственный SVG/CAD engine. Документировать технологический пробел, сравнить не менее двух кандидатов, указать фактический создатель алгоритма, установить `--help` и тестируемый I/O. При адаптации чужого кода фиксировать лицензии, версию и сохранённые upstream компоненты.

## 4. Геометрическая постановка

### 4.1. Получение области размещения

Сначала создать и проверить физическую копию художественных границ: единицы и контроль размеров обязаны быть явными. Вычислить рабочие области по правилам укладки, не применяя бездумно inset ко всем цветовым зонам. Границы разных зон могут быть **одной общей границей**, поэтому двойной setback и непреднамеренный gap недопустимы. Производственные отступы описать в отдельном policy: у края панно, у внутреннего отверстия, между соседними плитками одной и разных зон.

### 4.2. Поле и направляющие andamento

Приоритет: (1) явно предоставленные художественные flow lines; (2) касательные/эквидистанты вдоль достоверных границ; (3) геометрически полученное поле с фиксируемыми условиями на пересечениях и сингулярностях. Для эллипса, волны и спирали проверять производные и дуговую длину, непрерывность направлений и фазовую привязку рядов. Узкие перешейки, острова и острые углы должны получать контролируемую стратегию `split/reorient/shorten/flag`, не случайную прямоугольную сетку.

### 4.3. Размещение физической детали

Каждый тайл — самостоятельный closed path, позиционированный вдоль локальной касательной. Контролировать distance-to-boundary, effective gap, минимальную ширину, площадь, поворот, потенциальные пересечения и тонкие осколки. Boolean clipping каждого тайла относительно своей зоны должен сохранять его идентичность; одну сложную path-combine операцию нельзя считать валидным размещением множества независимых деталей без проверки IDs и geometry.

Рассчитывать реальные площади/минимальные ширины после clipping. Обязательно стратегии для микрофрагментов: `merge`, `reflow`, `trim`, `manual`, `flag`. Простое удаление маленького элемента без повторной проверки пустот/заполнения запрещено. Любой порог минимальной площади задаётся параметром и оценивается совместно с минимальной шириной.

### 4.4. Маркировка, цвет и экспорт

Цвет/материал присваивается по `color_id`, каждый `tile_id` связывается с `zone_id`. При необходимости номера деталей ставить в point-on-surface/pole-of-inaccessibility и проверять вмещаемость; для слишком малых элементов выдавать callout. Номера цветов художественной палитры и номерам физических тайлов не присваивать один namespace.

Prepress: сохранять mm, реальные размеры страницы, PDF boxes и запрет `fit-to-page`; при многолистовой компоновке делегировать размещение текста, легенды и панелей только в P, сохраняя B-масштаб. Если заказан лишь редактируемый layout SVG, не создавать обязательный PDF сверх задачи.

## 5. SKILL.md, интеграция, регрессия

`name: tessellation-mosaic-generator`; `description` trigger: *mosaic tesserae placement, andamento, flow-aligned curved tiling, cutter/assembly layout*. Негативные триггеры: sketch/photo preparation, palette numbering, decorative SVG assembly. Внутри `SKILL.md` должен быть полный рабочий процесс: input check → A→B mapping → tool selection → flow field → tile placement/clip → reflow → labels if requested → measured QA → export. Конкретные CLI/версии берутся из подтверждённой matrix, не из имён инструментов в developer-role.

Принимаемые инварианты: source A неизменен; все физические тайлы отдельно редактируемы; нет недопустимых перекрытий и самопересечений; замеры mm и gap соответствуют job tolerance; нет двойного offset и неоправданных пустот; `tile_id` стабильны при повторном прогоне с теми же параметрами, если алгоритм deterministic.

## 6. Fixtures, измерения и приёмка

| Fixture | Суть | Gate |
|---|---|---|
| T1 | Простое поле с однородными физическими ограничениями | tiles in mm, stable IDs, независимость деталей |
| T2 | Криволинейная лента/греческая волна вдоль эллиптической направляющей | tangent alignment, отсутствие rectangular grid, shape preservation |
| T3 | Соседние разноцветные области с общей границей | ровно одна политика gap, нет двойных отступов, безопасный clipping |
| T4 | Вогнутая зона с отверстием и острым углом | robust Boolean, no overlapping, корректные gaps/label positions |
| T5 | Узкая полоса с неизбежными микроосколками | `reflow/merge/flag`, полный manifest, отчёт о пустотах |
| T6 | Неопределён физический размер | `BLOCKED`, artwork без случайного масштабирования |
| T7 | PDF 1:1 и разбиение листов — только в print job | page size/boxes/physical geometry, визуальный print QA |

Сохранить исходный artwork, конечный layout/manifest и итоговый preview. Промежуточные stage outputs сохранять только для воспроизводимости дефекта или приёмки нового алгоритма. **Финальный контроль:** оценить геометрию, масштаб и зазоры по реально заданным производственным допускам; не пересчитывать каждое промежуточное действие при штатном выполнении. В new-session blind prompt без названия skill Codex должен выбрать тесселяцию, затребовать только недостающие manufacturing параметры и не начать трассировать source заново.

`PASS` — физический результат доказан данными/визуально и повторим; `FAIL` — картинка без отдельных тайлов, неверные швы/масштаб/направление, silent dropped fragments; `UNPROVEN` — неисполненная операция; `BLOCKED` — отсутствие необходимой геометрии/разрешения.

## 7. Порядок исполнения и результаты

**Stage 1:** inventory и валидация художественного входа. **Stage 2:** сравнение готовых алгоритмов с измеренным test. **Stage 3:** A→B mapping и independent QA. **Stage 4:** flow lines и placement (T1/T2). **Stage 5:** clipping, microfragments, materials (T3–T5). **Stage 6:** optional prepress и T7. **Stage 7:** skill integration, blind test, regression. **Stage 8:** scoped diff/registry/report. Каждый этап должен дать свой необходимый функциональный результат; отдельный QA каждого вызова не нужен. При FAIL исправлять дефектную стадию и адресно повторять её испытание.

Поставка: рабочий `SKILL.md`, параметры и тесты реально выбранного исполнителя, physical SVG/manifests/QA, print samples только при соответствующем profile, подтверждённые capabilities. Не реализовывать общий 3D/CAD движок, не менять источники A и не запрашивать права выше необходимых.

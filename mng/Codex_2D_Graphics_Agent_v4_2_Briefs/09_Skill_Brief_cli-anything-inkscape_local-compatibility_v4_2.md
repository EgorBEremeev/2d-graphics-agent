# Project Brief — локальная совместимость `cli-anything-inkscape`

**Версия:** 4.2 · **Дата:** 11.11.2026  
**Тип:** самостоятельное задание на project-level сопровождение **внешнего инструментального skill**, без переписывания upstream.  
**Проект:** `C:\gitCreative\solo-learn-mosaic`.  
**Проверяемый путь:** `.agents/skills/cli-anything-inkscape/SKILL.md` либо действительный discovered user-scope install.

**Режим проверок:** штатный вызов уже подтверждённого маршрута не сопровождается повторным `--help`, discovery, хешированием промежуточных файлов, DOM-diff после каждой команды или независимым рендером каждой стадии. Тестовые fixtures ниже предназначены для **однократной приёмки нового/изменённого навыка** и адресной регрессии после изменения его контракта. В обычном задании выполняется минимальная проверка конечного результата; промежуточная диагностика — при неизвестном интерфейсе, наблюдаемом сбое или реальном риске потери геометрии/масштаба. Не создавать подробный QA-log при штатном успешном исполнении.

## 1. Цель и пределы

Сформировать однозначную, проверяемую границу применимости установленного `cli-anything-inkscape` в проекте 2D-графики и убрать ложную маршрутизацию **существующих SVG** на интерфейс стороннего harness, который локально может принимать **только собственный JSON-проект**. Должно сохраниться полезное подмножество его реальных операций; независимый прямой `inkscape.com` CLI не смешивается с обёрткой.

Постановка **не** требует разработки нового wrapper, модификации upstream `SKILL.md`, установки нового Inkscape, починки неизвестного чужого репозитория или написания универсального SVG parser. Основная работа — диагноз фактического поддерживаемого контракта, минимальная локальная документация ограничений и безопасный route/validation. Если установленного skill нет, задокументировать `ABSENT`, а не создавать фиктивный исходник.

## 2. Preflight и воспроизводимый capability-test

1. Найти **реальный** путь, источник и версию `SKILL.md`, вызовы harness/entry point и supported commands/JSON schema. Однократно проверить `--help` только неизвестного интерфейса; не хешировать каждый файл и не перепроверять отдельно нативный `inkscape.com`, если его совместимость уже подтверждена для целевой операции.
2. На **отдельном тестовом JSON-проекте** выполнить примитив и текст, сохранить native project/output, проверить содержимое и результат независимым renderer. Только после этого отмечать JSON project generation как `VALIDATED`.
3. На внешнем простом корректном `test.svg` выполнить **неразрушающий** попытку чтения/импорта, если такая операция задекларирована harness. Если фактически получается `JSONDecodeError` или формат не поддерживается, классифицировать `UNSUPPORTED_INPUT`; не проводить небезопасных повторов на пользовательском SVG.
4. Проверить, реализованы ли Boolean действия в данном исходном коде либо являются placeholders. Наличие help-команды не доказывает реальное изменение фигуры: на простом пересечении прямоугольников/окружностей сверять expected postcondition + geometry/render.
5. Независимо воспроизвести при необходимости `inkscape.com --actions` headless `paste-in-place` на тестовой композиции. Возврат 0 без изменения выходной структуры → `NO_OP_UNEXPECTED` именно **native action в данном режиме**, а не «JSON harness не умеет импорт».

**Не воспроизводить уже доказанный локальный дефект без причины:** при наличии пригодной записи с версией и evidence выбирать fallback сразу. Новые либо противоречащие наблюдения проверить одним минимальным безопасным case; в таблице зафиксировать только то, что влияет на маршрутизацию.

## 3. Ограничения и артефакт `LOCAL_LIMITATIONS.md`

Если установлен проектный `SKILL.md`, разместить рядом `.agents/skills/cli-anything-inkscape/LOCAL_LIMITATIONS.md`, не изменяя оригинал. В документе должны быть:

- version/origin/hash и дата test; как invoked harness отличается от нативного Inkscape CLI;
- таблица фактически supported/unsupported capabilities: входы, выходы, ограничения операций, условия запуска и scopes;
- явное правило: существующие SVG из внешнего редактора не передавать в JSON-only harness как native project; разрешённая генерация простых фигур/текста — только в подтверждённой tested форме;
- конкретные ограничения, включая неподдержанные Boolean placeholders, **если** подтверждены исходным кодом/операцией;
- доступные маршруты для внешнего SVG: нативный Inkscape CLI/action, проектный `inkex/Shapely` runner или другой проверенный renderer; ссылки на source/fixture/evidence;
- правило обновления записи при смене версии и наблюдении новых возможностей.

**Важная инженерная особенность:** соседний `LOCAL_LIMITATIONS.md` сам по себе **не гарантирует**, что Codex прочитает его при активации чужого Skill. В действующем проектном `AGENTS.md` описать preflight чтения этого файла **до** использования JSON harness, а для автоматизации при необходимости оформить отдельный **project wrapper skill с другим именем**, с тестом фактической активации. Не считать случайное расположение двух файлов доказанной политикой безопасности.

## 4. Коррекция маршрутов остальных skills

Проверить `AGENTS.md`, `docs/agent/README.md`, `docs/agent/capability-matrix.md` и все действующие project `.agents/skills/**/SKILL.md` на формулировки вида «для любого SVG сначала вызвать cli-anything-inkscape». Заменить их на **проверку совместимого входа**, затем выбор реально работающего нативного CLI/API. Для sketch/photo обработки, paintbynumbers-adapter, native labeler, tessellation и document assembly правило одинаковое: JSON-only harness **не** получает внешний SVG, но проектный основной Codex продолжает иметь прямые SVG инструменты.

Отдельно сохранить различие: `CLI binary installed` ≠ `Tool SKILL present` ≠ `Tool selected in session` ≠ `Operation proved`. Внесение одной матричной строки не гарантирует изменения поведения — его надо проверить. Не заменять upstream SKILL псевдо-копией; при необходимости отдельный project wrapper обязан иметь правильные frontmatter `name/description` и явную ссылку на локальную политику.

## 5. Acceptance fixtures и поведение

| Fixture | Ожидаемый исход |
|---|---|
| C1 — собственный JSON project | Создан правильный primitive/text project/output; capability отмечается VERIFIED/VALIDATED только после QA |
| C2 — внешний `test.svg` | Если JSON-only, заранее `UNSUPPORTED_INPUT` и выбор alternative SVG CLI; source unchanged |
| C3 — Boolean placeholder | Ненастоящая операция не принимается по exit=0; semantic geometry test и зарегистрированный quirk |
| C4 — native headless `paste-in-place` | Для воспроизводимого no-op — `NO_OP_UNEXPECTED`; Document Assembly по параметризованной утилите вместо GUI |
| C5 — новый Codex session, SVG task без tool names | Agent не направляет SVG на несовместимую JSON обёртку, выбирает фактически допустимый инструмент |
| C6 — новый Codex session, primitive-from-scratch task | Harness допустим и применяется только если именно эта способность VALIDATED; нет глобального запрета на весь пакет |

**PASS:** оригинальный чужой `SKILL.md` остался цел, известные quirks имеют подходящее evidence (новый repro нужен только неподтверждённым фактам), конфликт маршрутов устранён и два естественных входных варианта C5/C6 проверены в одной целевой сессии. **FAIL:** файл с ограничениями создан, но агент его не читает; неподтверждённая «исправленная версия»; silent GUI; вывод «всё поддерживается» по `--help`.

## 6. Последовательность и поставка

**Stage 1:** обнаружить installed skill и установить provenance без массового хеширования. **Stage 2:** проверить только неподтверждённые C1–C4; известные ограничения перенести с evidence. **Stage 3:** `LOCAL_LIMITATIONS.md` и полезные capability entries. **Stage 4:** исправить ссылки project skills/AGENTS, не меняя upstream. **Stage 5:** одна целевая новая сессия с двумя вариантами ввода для проверки выбора совместимого инструмента. **Stage 6:** scoped diff, сохранность originals и короткий report.

В выходе должны быть только реально оправданные файлы: `LOCAL_LIMITATIONS.md` при установленной проектной обёртке, изменения project route/операционного контракта, candidate/validated matrix, repro fixtures и transcript. Если конкретный путь находится в user-scope вне репозитория и пользователь не разрешил изменение, не копировать его в project scope автоматически: документировать фактический location и проектную политику, статус `BLOCKED` для недоступного изменения.

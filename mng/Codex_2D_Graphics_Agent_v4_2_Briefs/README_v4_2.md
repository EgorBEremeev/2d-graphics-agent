## Порядок исполнения и объём проверок

Начать с `07`. Разделы 3–4 задают **четыре концептуальных уровня**, правила их изменения и детальные **требования к проектированию** инструкций: перечисленные требования нельзя использовать как полуготовые тексты для вставки в `developer_instructions` и `AGENTS.md`. До перехода к инструментальному рефакторингу необходимо пройти содержательную и runtime-приёмку инструкций по воротам G2. Затем изменять только компоненты, действительно затронутые текущей постановкой. Не создавать отсутствующие проекты/скрипты под ожидаемым именем без инвентаризации. Новые навыки реализуются отдельными заданиями, их наличие в этом комплекте не является доказательством готовности.

В штатной графической работе **не** запускать проверку каждого промежуточного CLI-вызова. Принятые инструментальные маршруты повторно не исследовать. Новые интерфейсы испытывать однократно, после ошибок применять адресную диагностику; готовый результат проверять соразмерно рискам задания. При приёмке конфигурации достаточно ограниченного набора функциональных и поведенческих проверок, определённого в главном брифе.

# Project Brief — `sketch-mosaic-pre-vectorizer`

**Версия:** 4.2 · **Дата:** 11.11.2026  
**Тип:** самостоятельное задание на проектный Codex Agent Skill  
**Проект:** `C:\gitCreative\solo-learn-mosaic` · **Режим:** headless/CLI/API с независимой визуальной проверкой.

**Режим проверок:** штатный вызов уже подтверждённого маршрута не сопровождается повторным `--help`, discovery, хешированием промежуточных файлов, DOM-diff после каждой команды или независимым рендером каждой стадии. Тестовые fixtures ниже предназначены для **однократной приёмки нового/изменённого навыка** и адресной регрессии после изменения его контракта. В обычном задании выполняется минимальная проверка конечного результата; промежуточная диагностика — при неизвестном интерфейсе, наблюдаемом сбое или реальном риске потери геометрии/масштаба. Не создавать подробный QA-log при штатном успешном исполнении.

## 1. Назначение

Подготовить или привести в работоспособное состояние `.agents/skills/sketch-mosaic-pre-vectorizer/SKILL.md` для преобразования **эскиза, линейного орнамента или чистого графического изображения** в редактируемые **замкнутые художественные зоны**, а не просто в красивые векторные обводки. Исполнитель — основной Codex с проектными инструкциями, а данный skill определяет узкую технологическую процедуру и выбор реальных raster/vector инструментов.

Цель — восстановление художественной структуры рисунка с его контурами, внутренними областями, палитрой/цветовыми классами и устойчивыми IDs; выбирать между трассировкой и параметрической реконструкцией повторяемого мотива по результатам испытаний. Цветной SVG и геометрия областей остаются в координатах изображения: **нельзя** вводить размеры изделия, швы, физическую плитку, PDF 1:1 и монтажные припуски.

Не применять данный skill к фото фактически уложенной мозаики (это другое распознавание), к готовому SVG для нумерации, к производственной тесселяции или к Document Assembly.

## 2. Вход и контракт выхода

**Вход:** `source.png/jpg/tiff` либо иной поддержанный raster; optional параметры: интерпретация линий (`separator / silhouette / decoration / ambiguous`), фон, инверсия, пороги, маски, палитра, предпочтительные мотивы/симметрии. Все параметры пространственной обработки заданы в пикселях исходника или долях текущего image space. Физические мм из соседних требований **не применяются**.

**Домен A:** source pixel coordinates → нормализованный `viewBox` SVG (преобразование явно записано). Для повторяемого мотива допустимо символическое геометрическое восстановление при сохранении художественной формы; итог должен быть сопоставим с исходником через overlay.

**Обязательные outputs:**

- `artwork_regions.svg`: выборочно редактируемые замкнутые зоны с устойчивыми `zone_id`, `color_id`, заливкой и действительными геометрическими границами; раздельные зоны одного цвета сохраняют собственные IDs.
- `artwork_regions.manifest.json`: `schema_version`, размеры исходника, `viewBox`, raster→SVG mapping, роль линий, workflow, параметры, происхождение CLI/версий, зона/палитра/неоднозначности; source hash только при требовании целостности/provenance.
- `preview_overlay.png`: проверяемое наложение контуров на исходный растр.
- `qa_summary.json`: компактный итог замкнутости и заметных отклонений для приёмки skill; в штатной задаче формировать, только если это часть действующего выходного контракта или требуется по риску.

`C_lay_boundaries.svg` допускается как совместимое имя **тождественного artwork-контракта**, не как стадия физического offset. Сохранять неизменный исходный raster и параметры обработки; не присваивать тайлам `zone_id`.

## 3. Инструменты и обязательный выбор маршрута

При разработке или изменении skill однократно сверить проектные `AGENTS.md`, route map, capability matrix и действующие skills. Для уже подтверждённых маршрутов не повторять `Get-Command`, `--help`, проверку версий и probe; при неизвестном интерфейсе достаточно одной совместимой пробы. Кандидаты: ImageMagick (preprocessing), Potrace (binary trace), VTracer (color/binary trace), прямой Inkscape CLI (редактирование путей, реальные actions и экспорт), обнаруженные готовые vectorization skills, специализированные геометрические функции для нормализации.

`cli-anything-inkscape` **не** является универсальным средством импорта внешних SVG: использовать только при подтверждённой совместимости фактического формата проекта/операции; при локально документированной JSON-only реализации такой импорт запрещён. Прямой Inkscape CLI и сторонний harness — разные исполнители. `cli-anything-gimp` использовать лишь если доказана конкретная пригодная растровая операция; не обещать полноценные фильтры GIMP по названию harness. `cli-hub-meta-skill` — средство discovery, не трассировщик. Все candidates сверить с локальным состоянием, не ставить FreeCAD из-за одной кривой.

Для нового класса эскизов, если подтверждённый путь оказался непригоден, сравнить до двух применимых методов на общем fixture: бинаризация+Potrace, VTracer, native trace или геометрическая реконструкция. Проверять форму, число зон, граф соседства, сложность путей, edge error, воспроизводимость и лицензии. Если повторяемая операция уже принята и вход попадает в тот же tested envelope, не проводить бессмысленный discovery заново.

**Политика разработки:** `reuse → adapt → build narrow gap`. Узкие скрипты допускаются для конвертера форматов/пред- и постпроверки; собственный raster vectorizer вместо доступного доказанного решения не допускается. Новый проектный CLI должен иметь параметризованный вход и настройки, тесты, не содержать координат под один рисунок, быть честно обозначен как newly built.

## 4. Требования к алгоритму и SKILL.md

`SKILL.md` обязан иметь валидные `name` и `description`, в котором *line sketch / ornament / clean drawing → closed editable artwork regions* является положительным триггером, а mosaic photograph, physical tessellation, numbering and assembly — отрицательными. Документировать доступные версии и entry points через capability matrix, не копировать туда полный `--help` внешних инструментов.

Исполнимый workflow:

1. Получить source, проверить размеры, alpha/color, повреждения и права; определить, что штрих обозначает: границу зоны, силуэт материала или декор. Не объявлять неопределённые штрихи границами автоматически.
2. Выбрать маршрут; создать рабочую копию и получить нормализованный raster, фиксируя image-space transforms. Сохранять исходную топологию и значимые мелкие элементы.
3. Преобразовать рисунок в области. При регулярном мотиве проверить симметрии, касательные, повторения и сохранение точной формы; **не** заменять криволинейный орнамент ортогональной сеткой.
4. Нормализовать пути: замкнутость, fill-rule, holes, shared boundaries, дубль контуров, self-intersections, draw order/visibility; неподдержанные SVG semantics диагностировать.
5. Сопоставить ID/палитру; записать `viewBox`, overlay transform, ambiguous zones. Не вводить физические offsets, tile gaps или `fit-to-page`.
6. Перед сдачей проверить итоговую структуру художественных зон и один сопоставимый overlay; промежуточные CLI-операции без признаков проблемы не перепроверять.
7. При FAIL — сменить параметры или способ; при нерешённой неоднозначности выставить `NEEDS_REVIEW/UNPROVEN` с конкретными местами, а не дорисовать произвольно.

Метрики подбирать **до** просмотра результата по характеристикам fixture: допустимая edge deviation в image units, число/площадь зон, число несохранённых компонент, доступность zone IDs, визуальные допуски. Грубая «красивая» трассировка без топологии не проходит.

## 5. Проверки и acceptance fixtures

| Fixture | Вход | Проверяемое |
|---|---|---|
| S1 | Чёткий 2–3-цветный замкнутый орнамент | Число/соседство областей, точность контуров, stable ID, editable SVG |
| S2 | Тонкие и прерывистые штрихи с неоднозначными ролями | Разделение видимых зон и линий, зафиксированные ambiguities без выдумывания структуры |
| S3 | Геометрический мотив с кривой, повторением и направляющей | Сохранение формы/кривизны, отсутствие прямоугольной сетки, разумное число узлов |
| S4 | Незамкнутые линии, самопересечения, остров/отверстие | Предсказуемый отказ либо корректная нормализация, topology QA |
| S5 | Изображение без физической размерности | В output/вопросах нет необязательных мм, швов, размеров плитки |

Проверка CLI: `--help` не считается реальной трассировкой, hash изменённого файла не является доказательством новых валидных областей. Сохранять output и независимый preview. Поведенческий test при принятии или изменении маршрутизации: в общей целевой Codex-сессии используется естественное задание без названия skill; в trace видны классификация, загрузка предметного skill, действительный исполняемый raster/vector CLI и QA до отметки PASS.

**PASS:** все заявленные обязательные fixtures с геометрией/overlay/manifest, инструментальный путь реально исполнен и выбран агентом. **FAIL:** невалидная геометрия, мнимый tool invocation, несанкционированный производственный scale. **UNPROVEN:** тест не проведён; **BLOCKED:** конкретный необходимый ресурс отсутствует/требует прав.

## 6. Поставка и этапы

**Stage 1** inventory/preflight существующего skill и маршрутов → **Gate:** ясно, что уже доступно/что отсутствует.  
**Stage 2** выбор/малые probes 2 методов → **Gate:** измеренный route decision.  
**Stage 3** контракт художественных зон и реализация минимально нужного интерфейса → **Gate:** S1 и S3 валидны.  
**Stage 4** SKILL.md/зависимости/вызов → **Gate:** обнаружение и исполнение.  
**Stage 5** S1–S5, QA, негативные результаты, new-session test → **Gate:** evidence.  
**Stage 6** scoped diff, registry update только с доказательствами, report/коммит в разрешённых пределах.

Если skill уже подтверждённо работает, сохранять код и выполнять только необходимое исправление маршрутизации/регрессию. Не переписывать работающий pipeline для совпадения с текстом брифа. Результат: действующий skill, его минимальные references/scripts если потребовались, воспроизводимые параметры, SVG/manifest/overlay/QA fixtures, обновление capability matrix только при появлении нового подтверждённого ограничения/маршрута и понятный способ повторного применения.

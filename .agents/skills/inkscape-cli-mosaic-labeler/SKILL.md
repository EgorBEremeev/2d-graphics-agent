# Контуры и номера цветов

## Вход и границы

Нужен цветной SVG с замкнутыми областями и каталог результата. Осмотри рисунок: различи залитые зоны, отверстия, перекрытия и малые острова. Сохраняй исходный файл. Работай в координатах SVG/viewBox; физические размеры и PDF нужны только по отдельному заданию печати.

Исполнитель — [mosaic_labeler.py](../../../tools/extensions/mosaic_labeler.py): готовые inkex и Shapely читают геометрию/стили и размещают метки, Inkscape измеряет текст и отрисовывает результат. Runner использует native SVG API. Его подтверждённый контракт — [матрица](../../../docs/agent/capability-matrix.md). Известный маршрут повторного help/probe не требует.

## Запуск

Все команды выполняются из корня проекта. `$inputSvg` — абсолютный путь к входу, `$jobDir` — абсолютный путь к каталогу результата. Нужны проектный Python в .venv-graphics и Inkscape в .tools-graphics/inkscape. Если среда отсутствует, используй [руководство по среде](../../../docs/environment/setup.md), регламент подготовки.

```powershell
& '.\.venv-graphics\Scripts\python.exe' 'tools\extensions\mosaic_labeler.py' $inputSvg --output_dir $jobDir --output (Join-Path $jobDir 'structural_layout.svg')
```

Параметры добавляются к этой команде:

- `--palette_map <path>` — сохранить ранее назначенные номера; новые цвета дополняют карту. Явно указанный несуществующий файл — ошибка; карта обязана содержать colors с уникальными положительными целыми номерами (JSON true не номер). Входная карта не перезаписывается, дополненная копия сохраняется в jobDir. Без карты номера детерминированы по нормализованному HEX. Раздельные области одного цвета получают одинаковый номер, сохраняя свои ID.
- `--font_size`, `--min_font_size`, `--stroke_width` — размеры в SVG units; `--min_area` — площадь в units², `--min_width` — порог узкости.
- `--micro_policy flag` — стандартный режим: сохранить малые области и отметить их. `keep` сохраняет без отметки. `merge` применять только по явному запросу вместе с `--allow_geometry_change true`: объединение со смежной зоной меняет геометрию и записывает переход площади/цвета/ID.
- `--artwork_manifest <path>` — сохранить исходные color_id/zone_id из карты областей. Одноимённый artwork_regions.manifest.json рядом со входом подхватывается автоматически; явно переданный отсутствующий manifest — ошибка.
- `--flatness` — точность аппроксимации кривых для расчётов; исходные контуры в обычном режиме остаются неизменными.

## Проверка и результат

1. Проверь код завершения и qa_summary.json. В обычном режиме должны сохраняться исходные геометрические атрибуты, строки transform и viewBox. Если у входа VTracer нет viewBox, он выводится из width/height без назначения физического масштаба.
2. Осмотри сохранённый SVG через его preview_overlay.png: заливки убраны, контуры серые, номера читаются. Каждый номер должен соответствовать palette_map.json и находиться целиком внутри видимой зоны либо иметь однозначную выноску. Проверь отверстия, общие границы и малые острова.
3. При FAIL исправь причину в пределах задания: параметры, нормализацию входа или положение меток. Неподдерживаемую конструкцию сообщи с указанием объекта; результат с потерянными зонами не принимай.

Передай structural_layout.svg, palette_map.json, qa_summary.json, preview_overlay.png и компактный manifest.json с входом, параметрами и ограничениями. Номера остаются отдельными редактируемыми текстами. При неравномерном affine ширина обводки имеет диапазон, записанный в QA; её максимум равен stroke_width.

Runner диагностирует use/image, clip/mask/filter, gradient/pattern, несовместимый viewport/viewBox и сложное прозрачное смешение с цветным подслоем. Для таких входов требуется явная нормализация. Он запускается как Python/inkex entry point; ID расширения не является подтверждённой headless-командой Inkscape.

Временный профиль очищается автоматически через tools/inkscape/runtime.py. В каталоге результата служебные профили не сохраняются. Установка расширения в GUI не нужна для этой команды; если она отдельно запрошена, tools/extensions/install_profile.py устанавливает один проектный профиль .tools-graphics/inkscape-mosaic-profile.

## Контракт интеграции и альтернативы

Фактический интерфейс сохраняет позиционный SVG, `--output_dir` и стандартный inkex `--output`. Примерные `--input/--out-svg/--mode/--config` из брифа не являются флагами этой реализации; совместимый действующий CLI выбран, чтобы сохранить прежние extension/runner вызовы. preserve_geometry — стандартное поведение; только явные micro_policy merge + allow_geometry_change разрешают изменение. Результаты имеют фиксированные предметные имена внутри переданного jobDir.

manifest.json envelope 1.0 содержит source, coordinate_domain=A, viewBox, objects со стабильными ID/номерами, provenance, параметры, warnings и qa_ref; прежние output/method/source_sha256 сохранены. inkex разбирает пути, стили и transforms; Shapely polygonize/видимая разность/polylabel проверяют области и размещают номера; проектная связка управляет палитрой/выносками; native query-all измеряет текст, exporter создаёт preview. Это составной проектный runner, не штатная команда нумерации редактора.

Данный маршрут — альтернатива будущему vector-svg-to-numbered-contours. Выбирай один по совместимости и геометрии; второй не является следующей обязательной стадией и пока отсутствует. Для unsupported SVG требуется нормализация известным средством или квалифицированный отказ. Компоновку готовой схемы и легенды передавай document-assembly, физическую раскладку — отдельной компетенции.

Адресная приёмка writer/map контракта — tests/labeler/verify_v4_2.py --out <каталог artifacts>; широкая прежняя геометрическая приёмка относится к исходной установке. В обычном задании они не запускаются автоматически.

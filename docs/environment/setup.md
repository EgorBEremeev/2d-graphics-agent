# Подготовка и восстановление среды Windows

Эта инструкция предназначена агенту, который подготавливает среду для владельца. Для выполнения нужны Windows, PowerShell 5.1 и установленный [uv](https://docs.astral.sh/uv/); глобальные Python, Git и внешний архиватор не предполагаются. Агент сам определяет и подставляет значения переменных, выбирает поставки и выполняет применимые команды. Владельцу не требуется подбирать пакеты, URL или пути.

## Исходные условия и выбор состава

Из открытого корня клона вычисли проектные пути и архитектуру ОС:

```powershell
$root = (Get-Location).Path
$architecture = [System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture.ToString()
$env:UV_PYTHON_INSTALL_DIR = Join-Path $root '.tools-graphics\python'
$env:UV_CACHE_DIR = Join-Path $root '.uv-cache'
```

Сначала прочитай [карту подготовленной среды](2d-environment.md), [матрицу](../agent/capability-matrix.md), [каталог tools](../../tools/README.md) и применимый skill. Из контракта выбранного модуля и официальной документации его средств определи приложение и формат поставки для этой Windows/архитектуры, нужный язык и окружение, зависимости, ресурсы, лицензии и точки входа. Найди версии, совместимые с выбранным интерфейсом; закреплённые Python-зависимости библиотеки бери из её requirements. Не подготавливай всё перечисленное для произвольной графической задачи. По явному запросу всей библиотеки состав — объединение требований всех переносимых tools и skills, включая факультативное отдельное plotter-окружение; тестовые зависимости добавляются только при отдельной работе с тестами.

Проверь, есть ли уже пригодные компоненты в карте и по указанным ею путям. Совместимые компоненты используй повторно; не перезаписывай существующую установку и пользовательские настройки. Наличие и версия средства, импорт пакета и доступность интерфейса подтверждают только подготовку установки. Графическую операцию оценивай по [операционному контракту](../agent/graphics-model-behavior.md) при выполнении графической задачи.

## Правила размещения и выбора установки

Агент определяет состав по выбранной операции, требованиям исполнителя, его skill и официальной документации. Для любой новой поставки сначала проверь, не задаёт ли исполнитель обязательный путь или явно поддерживаемый параметр пути. Если задаёт — используй этот контракт; если нет — выбери проектное расположение по правилам ниже. Не подготавливай средство только потому, что оно перечислено в другом маршруте.

| Категория | Правило размещения и настройки |
|---|---|
| Приложение или отдельный CLI | Полную поставку с DLL и ресурсами размести в проектном `.tools-graphics/<имя-средства>/`, если контракт исполнителя не требует другого места. Запиши точку входа и официальный источник в карту. Уже установленное совместимое средство используй по существующему пути только если исполнитель поддерживает такой путь; если путь зафиксирован в скрипте, обеспечь именно его без изменения интерфейса. |
| Язык выполнения и пакетный менеджер | Недостающий интерпретатор получи через uv или официальную поставку; управляемые uv Python размещай в проектном `UV_PYTHON_INSTALL_DIR`. Другие средства размещай отдельно по их официальному способу установки, не меняя глобальное окружение без необходимости. |
| Зависимости | Устанавливай пакеты в окружение соответствующего исполнителя, отдельно от системного Python и от несовместимых окружений. Закреплённые версии бери из requirements выбранного модуля; общий проектный venv размещай в `.venv-graphics/`, если исполнитель не требует другого пути. Для несовместимых или факультативных наборов создай отдельное окружение внутри `.venv-graphics/<имя-маршрута>/` по его контракту; бинарные зависимости разных Python и архитектур не смешивай. |
| Ресурсы | Шрифты, модели и другие нужные данные получай из официального источника, проверяй лицензию и помещай в отдельный проектный каталог под `.tools-graphics/` либо в место, требуемое исполнителем. Передавай фактический путь через поддерживаемый параметр или настройку; не задавай один ресурс всем задачам. |
| Профили и кэши | Постоянный профиль выбранного средства размещай в `.tools-graphics/` отдельно от результатов задачи. Для переносимых runners временные профили, TEMP и TMP создаются в `.cache/graphics/` через `tools/inkscape/runtime.py`. Загрузки сохраняй в `.downloads-graphics/`, кэш uv — в `.uv-cache/`; не меняй пользовательский AppData. |
| Необходимые распаковщики | Используй доступные средства Windows; недостающий распаковщик получи через uv или официальную поставку и расположи отдельно от результата. Сохраняй полную структуру распакованного приложения. |

Для фактического вызова вычисляй пути от корня проекта и передавай их через интерфейс выбранного средства; переменные окружения задавай на время процесса. Фактические места, версии, зависимости и ограничения записывай в [карту среды](2d-environment.md), а не предполагай их по этим правилам. Предыдущую совместимую установку используй повторно.

## Окружение и зависимости

Если выбранному средству нужен Python, агент определяет `$pythonVersion` по его требованиям, а `$venvDir` — по правилам размещения и контракту исполнителя. Если совместимое окружение уже есть, используй его после проверки; иначе получи Python и создай отдельный venv:

```powershell
uv python install $pythonVersion
if ($LASTEXITCODE -ne 0) { throw 'Не удалось получить Python.' }
if (-not (Test-Path -LiteralPath $venvDir)) {
    uv venv $venvDir --python $pythonVersion
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать окружение.' }
}
$python = Join-Path $venvDir 'Scripts\python.exe'
if (-not (Test-Path -LiteralPath $python -PathType Leaf)) { throw 'Нет точки входа Python; проверь существующее окружение.' }
```

Агент определяет массив `$names` и путь `$requirements` по выбранному модулю. Для требований с закреплёнными версиями найди нужные строки и передай их uv; при отсутствии закреплённой версии используй официальный контракт конкретного средства, не создавая фиктивный pin. Для отдельного маршрута, которому требуется изоляция, повтори подготовку с другим `$venvDir` и соответствующим requirements. Не устанавливай тестовые пакеты, пока не запрошена работа с тестами.

```powershell
$lines = [IO.File]::ReadAllLines($requirements, [Text.UTF8Encoding]::new($false, $true))
$pins = @($lines | Where-Object { ($_.Split('=')[0]) -in $names })
if ($pins.Count -ne $names.Count) { throw 'Для одного из пакетов не найдена закреплённая версия; проверь требования средства.' }
uv pip install --python $python $pins
if ($LASTEXITCODE -ne 0) { throw 'Установка зависимостей не завершена.' }
```

## Получение и размещение поставки

Когда выбранному маршруту требуется отсутствующая поставка, агент выбирает официальный источник, совместимые версию и архитектуру, определяет опубликованную сумму и заполняет переменные ниже по данным этого источника. `$distributionUrl` — прямой URL, `$archiveFormat` — `zip` или `7z`, `$publishedHash` — опубликованная сумма либо пустая строка при её отсутствии, `$hashAlgorithm` — опубликованный алгоритм. `$archive` и `$stage` создаются как уникальные проектные пути для конкретной поставки. Сумму проверяй до распаковки; при несовпадении прекрати установку. Если сумма не опубликована, укажи это в записи результата.

```powershell
$downloads = Join-Path $root '.downloads-graphics'
New-Item -ItemType Directory -Force $downloads | Out-Null
$nonce = [Guid]::NewGuid().ToString('N')
$archive = Join-Path $downloads ('distribution-' + $nonce + '.' + $archiveFormat)
$stage = Join-Path $downloads ('unpacked-' + $nonce)
if ($archiveFormat -notin @('zip', '7z')) { throw 'Для формата поставки нужен соответствующий официальный способ распаковки.' }
if ((Test-Path -LiteralPath $archive) -or (Test-Path -LiteralPath $stage)) { throw 'Выбери свободные пути загрузки и распаковки.' }
Invoke-WebRequest -UseBasicParsing -Uri $distributionUrl -OutFile $archive
if ($publishedHash) {
    if ($hashAlgorithm -notin @('SHA256', 'SHA1')) { throw 'Укажи опубликованный алгоритм контрольной суммы.' }
    if ((Get-FileHash -LiteralPath $archive -Algorithm $hashAlgorithm).Hash -ne $publishedHash.Trim()) { throw 'Контрольная сумма не совпадает.' }
} else {
    Write-Output 'Опубликованная контрольная сумма отсутствует; зафиксируй это в карте.'
}
if ($archiveFormat -eq 'zip') {
    Expand-Archive -LiteralPath $archive -DestinationPath $stage
} else {
    uv pip install --python $python py7zr
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось подготовить распаковщик.' }
    & $python -m py7zr x $archive $stage
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось распаковать поставку.' }
}
```

Для `7z`, если у выбранного маршрута ещё нет Python, предварительно получи Python и создай отдельное служебное окружение через uv, затем укажи его Python в `$python`. Для другого формата агент находит официальный совместимый способ распаковки или получает нужное средство через uv либо официальную поставку; сохраняет лицензии, DLL и ресурсы.

После распаковки определи полный каталог поставки `$distributionRoot` и проектный `$destination` по требованиям выбранного модуля. Для распространяемого ресурса, например файла шрифта, выбери его путь и целевой каталог тем же способом. Следующий пример размещает полный каталог, сохраняя существующую установку:

```powershell
if (-not (Test-Path -LiteralPath $distributionRoot -PathType Container)) { throw 'Каталог поставки не найден.' }
if (Test-Path -LiteralPath $destination) { throw 'Целевой путь уже занят; сохрани существующие данные.' }
New-Item -ItemType Directory -Force (Split-Path -Parent $destination) | Out-Null
Copy-Item -LiteralPath $distributionRoot -Destination $destination -Recurse
```

При необходимости настрой профиль, локальные шрифты и переменные окружения по контракту средства и выбранного модуля; проектные вызовы и требования к ресурсам перечислены в [tools](../../tools/README.md) и skills. Если выбранный маршрут требует отдельный файл ресурса, агент выбирает фактический `$resourceFile` и `$resourceDir`, затем размещает ресурс без замены существующего:

```powershell
if (-not (Test-Path -LiteralPath $resourceFile -PathType Leaf)) { throw 'Файл ресурса не найден.' }
New-Item -ItemType Directory -Force $resourceDir | Out-Null
$resourceTarget = Join-Path $resourceDir (Split-Path -Leaf $resourceFile)
if (Test-Path -LiteralPath $resourceTarget) { throw 'Ресурс уже существует; проверь его совместимость.' }
Copy-Item -LiteralPath $resourceFile -Destination $resourceTarget
```

Если выбранное средство использует Fontconfig, агент назначает `$fontDirectory` и `$fontConfigDirectory` по подготовленному маршруту, затем создаёт локальную конфигурацию и переменные только текущего процесса:

```powershell
New-Item -ItemType Directory -Force $fontConfigDirectory | Out-Null
$fontXmlPath = [System.Security.SecurityElement]::Escape(($fontDirectory -replace '\\', '/'))
$configXml = @"
<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "fonts.dtd">
<fontconfig><dir>$fontXmlPath</dir></fontconfig>
"@
$fontConfigFile = Join-Path $fontConfigDirectory 'fonts.conf'
if (Test-Path -LiteralPath $fontConfigFile) { throw 'Конфигурация уже существует; проверь её и используй повторно.' }
[IO.File]::WriteAllText($fontConfigFile, $configXml, [Text.UTF8Encoding]::new($false))
$env:FONTCONFIG_FILE = $fontConfigFile
$env:FONTCONFIG_PATH = $fontConfigDirectory
```

Установка расширения остаётся отдельной операцией по запросу. Для подключения подготовленной среды см. [runtime](runtime.md).

## Проверка установки и фиксация результата

Для каждого подготовленного компонента проверь фактический путь, версию, требуемые импорты и доступность соответствующего интерфейса согласно его документации. Не выдавай наличие или импорт за доказательство графического результата. После установки **обнови [2d-environment.md](2d-environment.md)**, сохранив таблицу из трёх колонок:

- Во вводной записи укажи фактические дату подготовки, ОС и архитектуру.
- В «Средство» запиши название и фактически установленную версию приложения, библиотеки, обёртки или связанной группы.
- В «Расположение и источник» запиши действительную точку входа или каталог, источник поставки и существенные связи с окружением, архитектурой и зависимостями. Проектные пути сохраняй относительными, когда это возможно.
- В «Рабочая граница» запиши доступный интерфейс, условия и известные ограничения применимой версии со ссылкой на соответствующую строку [матрицы](../agent/capability-matrix.md). Отдельно укажи, что графическая операция установкой не проверена.

Если подготовка частичная, запиши только фактически подготовленные компоненты и конкретную причину препятствия; отсутствующему компоненту не приписывай состояние установленного. При повторном входе используй карту и совместимые установленные компоненты, подготавливая только недостающее. После изменения состава актуализируй карту; продолжение работы с готовой средой описано в [runtime](runtime.md).
